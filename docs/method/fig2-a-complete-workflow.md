# Fig. 2(a) 会话分析与候选筛选流程

## 这条流程在做什么

这条流程从原始 Agent 会话中筛选出适合作为候选语料的 session。它先恢复会话结构和用户任务，再核对 Agent 的实际行为与结果，随后生成任务标签、执行统一筛选，最后审计并交付入选 session。

**输入：** 原始 session，包含用户与 Agent 的交互，以及可能存在的工具调用、工具结果和产物信息。

**输出：** 经筛选和审计的原始 session，以及能够追溯任务分析、标签和筛选理由的关联信息。

```text
Raw sessions
    ↓
Normalize
    ↓
Understand & detect signals
    ↓
Verify & attribute
    ↓
Label
    ↓
Select
    ↓
Audit & export
    ↓
Selected sessions
```

六个步骤的作用可以概括为：**整理会话 → 理解用户任务 → 核实发生了什么 → 描述任务 → 按规则筛选 → 检查并交付结果。**

其中，用户的负面反馈只是需要进一步检查的线索。它本身不能证明任务失败，更不能直接证明 Agent 应负责任。是否入选仍由独立的 Prechecks 和 S1–S4 规则决定。

## 六个处理步骤

### 1. Normalize：整理会话，保留来源

**输入**

原始 session 记录，包括用户消息、Agent 回复、工具调用和结果、错误、附件或其他记录。

**做什么**

把记录整理成按顺序排列的事件和轮次，标明角色、事件之间的关系及其在原始来源中的位置。工具调用和工具结果要能关联，但“调用过工具”不能被当成“工具执行成功”。无法解析或不认识的记录也不能静默丢弃。

**产出**

标准化的 session、turn 和 event 序列，以及用于回查原始记录的来源位置和标识。

### 2. Understand & detect signals：理解任务，发现待核查信号

**输入**

标准化会话中的真实用户消息。

**做什么**

从用户表达中划分连续任务片段（Episode），初步恢复用户目标、需求及其变化，并标记值得在完整交互中核查的反馈信号。

这一步只看用户侧信息。它提出“接下来应该核查什么”，不判断 Agent 是否失败，也不归责 Agent。正常澄清、纠正、合理新增要求、中性追问或“继续”等推进性表达，不能仅凭字面自动算作痛点信号。

**产出**

- Episode 的起止位置；
- 初步目标、需求和需求变化，并附用户原文依据；
- 候选反馈信号及对应的用户消息引用；
- 对用户侧信息的初步判断和不确定项。

用户侧信息按历史分析框架整理为 R1–R8，具体内容见后文“用户侧分析的 R1–R8”。这些信息用于理解和路由，不是最终筛选规则。

### 3. Verify & attribute：核实任务结果，分析问题原因

**输入**

上一步形成的 Episode、初步目标与需求、候选信号；以及该 Episode 的完整交互记录，包括 Agent 回复、工具调用与结果、错误和可观察产物。

**做什么**

逐项核对用户要求是否满足，并判断候选信号是否对应真实问题。分析时要查看完整交互和结果，不能只根据用户反馈或上一步摘要下结论。工具调用只说明 Agent 尝试过某项操作；是否成功要看工具结果、产物、测试结果或其他可观察证据。

核验和归因分别回答不同问题：

1. 用户真正要完成什么？初步理解是否需要修订？
2. 每项需求是已满足、部分满足、未满足，还是证据不足？
3. 用户反馈对应真实问题，还是正常澄清、需求变化、权限限制或外部故障？
4. 问题是否与 Agent 有关？若有关，证据支持哪种原因？
5. 是否有足够证据指出具体的 Agent 能力缺口？若不足，缺什么证据？

必须把四件事分开记录：**用户是否表达不满、任务或需求是否失败、问题是否与 Agent 有关、Agent 是否暴露出具体能力缺口。** 前一项不能自动推出后一项。证据不足时保留待审，不猜测原因。

归因时要检查可能原因，例如 Agent 的推理或回答、执行或验证、工具使用、上下文、权限、外部因素、用户输入，以及目前无法确定的情况。若要判断 Agent 是否没有响应、没有执行或中途停止，应检查目标指令之后所有可观察到的 Agent、工具和产物事件。若用户主动打断导致回复不完整，不能仅凭输出不完整就判定 Agent 失败；打断本身也不能说明用户为什么不满。

Episode 结束后的明确用户反馈可以辅助判断用户是否查看或评价了交付物，但不能因此把 Episode 结束后提出的新要求倒算成原任务需求。

**产出**

经核验的目标与需求结果、问题记录、责任归因及理由、证据引用和未决事项。本步骤不决定任务是否通过 S1–S4。

### 4. Label：描述任务需要什么能力

**输入**

经核验的任务和需求、相关证据，以及统一的能力标签体系（taxonomy）。

**做什么**

将任务需求映射到 taxonomy 中的能力，并评估难度等任务属性。标签判断要有证据支持，不能只靠关键词匹配，也不能补写用户没有提出的验收条件。

这里的能力映射回答“**这个任务需要什么能力**”。第 3 步中的能力缺口回答“**核验到的 Agent 问题暴露了什么能力不足**”。两者相关但不是同一种标签，不能合并。

**产出**

结构化任务标签、能力映射、难度等属性、支持证据和仍未解决的判断。

### 5. Select：按统一规则决定是否入选

**输入**

任务标签、证据、适用范围和筛选规则（selection policy）。

**做什么**

先执行必要的结构、证据和范围检查（Prechecks），再按 S1–S4 判断任务是否满足候选语料的要求：

- **S1 Evidence-backed：** 至少有一个主要任务能力映射得到证据支持；只有辅助能力映射不够。
- **S2 Challenging：** 任务具有实质挑战；难度为 medium/high 可通过，已确认难度低可判不入选，难度未知则待复核。
- **S3 Recoverable goals：** 能否从会话中连贯还原任务目标和需求。
- **S4 Checkable outcome：** 能否依据记录判断任务结果或完成情况。

**产出**

筛选决定及逐项理由。决定包括 `selected`、`not_selected`、`pending_review` 和 `invalid`：规则通过才入选；已确认不满足条件则不入选；关键情况未知则待复核；结构或证据引用无效则标记无效。

R1–R8 的用户侧分析和第 3 步的问题归因都不能代替 S1–S4。候选反馈信号的有无、痛点是否确认或 Agent 是否失败，都不会自动让任务入选或出局。

### 6. Audit & export：检查决定并交付入选会话

**输入**

筛选决定、任务分析和标签记录、原始 session 及来源信息。

**做什么**

检查分析、标签、证据和原始来源是否能相互对应；验证数据结构、精确引用、来源快照及所用规则/产物版本；对可确定性复算的筛选规则重新计算；核对最终决定和导出清单是否一致。

**产出**

审计记录、入选 session 的原始数据，以及相关任务分析、标签、筛选理由、元数据和证据索引。

这一步交付的是经过筛选的会话语料，不等于已经构造好完整 benchmark task，也不代表 workspace 已获取、任务已验证可复现，或 Agent 曾成功完成任务。这些属于后续工作。

## 用户侧分析的 R1–R8

R1–R8 用于理解用户提出了什么、任务如何演进，以及哪些反馈值得核查。它们属于第 2 步的分析信息，不是 S1–S4 的筛选规则。

- **R1 目标领域：** 任务属于目标领域、相邻领域、范围外，还是暂时无法判断。
- **R2 初步分析价值：** 任务是否真实、有实质内容且原则上可验证。对话短不等于价值低；该判断不能取代最终筛选。
- **R3 Episode 边界：** 哪些连续交互属于同一任务。背景补充、澄清、纠正、重试和返工通常留在同一 Episode；出现独立交付目标时再考虑拆分。
- **R4 初始 Query：** Episode 中首次提出可执行核心任务的用户消息。
- **R5 Query 清晰度：** 只依据提出 Query 时已有的用户上下文，判断任务表述清晰、部分清晰或不清晰。
- **R6 初步目标与需求：** 从用户消息提取目标和具体需求，并记录原文来源。
- **R7 需求演进：** 区分澄清原意、纠正既有要求和真正新增的要求。
- **R8 候选反馈信号：** 标记值得回看完整交互的用户反馈，并保留连续原文和事件位置。

历史候选信号类型包括：明确拒绝、指出结果缺陷、重复强调约束、要求重做或回滚、失败后重试、用户接管、任务受阻或放弃。它们只是核查入口，不是 Agent 失败标签。

## 阅读流程时要区分的概念

| 概念 | 它回答的问题 | 它不能单独证明什么 |
|---|---|---|
| 候选反馈信号 | 哪些用户消息值得核查？ | Agent 已失败或应承担责任 |
| 需求/任务结果 | 用户要求是否满足？实际发生了什么？ | 问题必然由 Agent 导致 |
| Agent 责任归因 | 问题是否与 Agent 有关？可能原因是什么？ | 任务应自动入选 |
| Capability gap（能力缺口） | 已核实的 Agent 问题暴露了什么能力不足？ | 等同于任务能力标签 |
| Taxonomy mapping（能力映射） | 任务需要哪些能力？ | Agent 在本次会话中失败 |
| S1–S4 筛选 | 任务是否满足通用候选集标准？ | 已完成任务构造或复现验证 |
